# 通信・タスク管理ライブラリについて

本プロジェクト（Gen6-GSE-Elec）では、通信とタスク管理の効率化のために [hideakitai](https://github.com/hideakitai) 氏制作のライブラリを採用しています。
AVRマイコン（ATmega2560）で使用する際の**「独特な制約（落とし穴）」**と、その対処法についてまとめます。

---

## 1. MsgPacketizer（通信ライブラリ）
### 概要
RS485などのシリアル通信で、複雑なデータ（数値、配列など）を「パケット」として安全・簡単に送受信するためのライブラリです。

### 初心者がハマるポイント (AVR限定)
AVRマイコン（ATmega2560）ではメモリ節約のため、**「何種類のデータを受け取るか」**などの上限が非常に小さく設定されています。

| 項目 | デフォルト | 意味 | 制限を超えると... |
| :--- | :---: | :--- | :--- |
| **subscribe数** | **3** | `MsgPacketizer::subscribe` で登録できるIDの種類 | 4つ目以降の登録が**無視**され、通信が届かない。 |
| **Arrayサイズ** | **3** | 1つのパケットに詰め込める変数の個数 | 4つ以上のデータを送ろうとすると、受信側で失敗する。 |
| **パケットサイズ** | **96B** | 1パケットの最大バイト数 | 長すぎるデータは送信・受信できない。 |

### 対処法 (`platformio.ini`)
制限を増やしたい場合は、プロジェクトの設定ファイルに「上限を上書きする指示」を書きます。
```ini
build_flags = 
    -D PACKETIZER_MAX_CALLBACK_QUEUE_SIZE=8  ; subscribe数を8に拡大
    -D MSGPACK_MAX_ARRAY_SIZE=10             ; パケット内の変数個数を10に拡大
```

## 2. TaskManager（タスク管理ライブラリ）
### 概要
「1秒ごとにセンサ値を読む」「10Hzで通信を送る」といった複数の処理（タスク）を、`delay()` を使わずに「並行して動いているように」管理するライブラリです。

### 初心者がハマるポイント (AVR限定)
こちらもAVRマイコンでは、登録できるタスクの数に上限があります。

| 項目 | デフォルト | 意味 | 制限を超えると... |
| :--- | :---: | :--- | :--- |
| **メインタスク数** | **16** | `Tasks.add()` で登録できるタスクの総数 | 17個目のタスクが**起動しない**。 |
| **サブタスク数** | **4** | タスクの中でさらに `add` する際の上限 | 複雑な親子タスクを作る際に失敗する。 |

### 対処法 (`platformio.ini`)
シーケンス処理などを増やしてタスクが足りなくなった場合は、以下の指示を追加します。
```ini
build_flags = 
    -D ARX_VECTOR_DEFAULT_SIZE=32      ; タスク上限を32に拡大
    -D TASKMANAGER_MAX_SUBTASKS=8      ; サブタスク上限を8に拡大
```

---

## 3. ボードによる違い（重要）
この制約は、**「メモリの少ない古いマイコン（AVR）」**でのみ発生します。

*   **ATmega2560 など**: **上記制限あり**。`build_flags` で調整が必要。
*   **RA4M1 など**: **制限なし**。モダンな設計のため、メモリの許す限り自動で増えます。

## まとめ
「コードは間違っていないのに、なぜか通信が届かない・タスクが動かない」という時は、まず上記の **デフォルト上限** を疑ってください。基本的には `build_flags` で余裕を持った数値に設定しておくのが安全です。
